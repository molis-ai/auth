# Auth 控制台：部署初始化与管理网页

状态：V10 初始化、双语 Vue 控制台与 SDK 同源登录已实现，并完成下述隔离环境验收。Auth/SDK 整体仍在开发，不等同于生产部署或完整空间管理交付。

## 首次初始化

1. 按 [登录配置](login-protocol.md) 准备 MySQL、Redis 和真实的外部 `AUTH_ISSUER`，生产必须 HTTPS。使用 `-Pweb` 构建带页面的 Jar。
2. 部署设置 `AUTH_LOGIN_ENABLED=true`、`AUTH_EPHEMERAL_ENABLED=true`、`AUTH_CONSOLE_ENABLED=true`。
   可选 `AUTH_CONSOLE_CLIENT_ID` 默认 `molis-auth-console`，须是尚未被其他登录客户端占用的 ID，不能使用 `svc_` 前缀。
3. 启动时 Flyway V10 建立单行初始化锁。首次开启控制台时，在一个数据库事务中创建应用、WEB 公共登录客户端、`account profile` scopes、精确的 `${AUTH_ISSUER}/console/callback` 回调及初始化审计。
   应用动作目录为空，**不创建用户、密码、服务 Secret 或管理员授权**。
4. 打开 `${AUTH_ISSUER}/console`。没有会话时进入托管登录；首次用户从登录页切换注册，完成正常邮箱验证和密码注册。
   注册入口需要按 [邮件说明](mail-delivery.md) 配置可用邮件。开发收件箱仅用于隔离本机测试，不能代替生产邮件验证。
5. 登录完成后普通用户可查看自己的账号/userId、管理本人空间和处理邀请，不显示平台管理功能。部署方核对实际用户后，把该 userId 加入 `AUTH_PLATFORM_ADMIN_USER_IDS`，重启所有实例；用户重新进入控制台即可使用平台功能。

管理员白名单默认空。没有“首用户成为管理员”、邀请管理员、账号名称匹配提权、页面内修改白名单等入口。
不要把测试数据库里的 userId 或凭据复制到正式部署配置中。

## 重启、多实例及配置变更

- 初始化使用 MySQL 单行排他锁和事务，多个 Auth 实例共用同一个数据库时只创建一次；不是 JVM 单例锁。
- 重启不重置应用名、动作目录、回调、scope 或状态，不自动启用已停用配置。
- 同名登录客户端已存在但不属于初始化绑定时拒绝接管；修改已绑定的 `AUTH_CONSOLE_CLIENT_ID` 也启动失败，而不是另建控制台或静默改变绑定。
- 若控制台应用/客户端停用、丢失所需 scope、或没有当前 issuer 的回调，公开配置返回 console.enabled=false，页面提示部署检查，不绕过登记检查登录。
- 修改域名须在切换前明确登记新 origin 对应的精确控制台回调，并同步所有实例的 issuer。重启不会自动追加或覆盖回调。多实例 issuer/数据库/Redis/白名单配置须一致。
- 可以通过平台 API 停用自己的用户或控制台应用；确认提示会警告可能退出。没有末位管理员绕过规则。操作前应准备另一个有效部署管理员和部署侧恢复流程。
- 管理身份不等于业务空间成员：平台管理员仍不能读取自己不属于的空间。

## 网页能力

控制台路径为 `/console`，OAuth 回调为 `/console/callback`；静态资源随 Auth Jar 分发，不需要另起前端生产服务。
`GET /api/v1/auth/ui-configuration` 新增 `console: {enabled,clientId,redirectUri}`，只暴露公共客户端元数据，无管理员名单和秘密。

页面复用仓库内独立浏览器 SDK 源码，不复制登录协议、不要求产品使用 Vue：

- 托管登录、PKCE/state、授权码兑换，Access/Refresh 只在内存。
- 回调 URL 在异步读取配置前同步清理，原始回调只作为内存快照交给 SDK 验证。
- 刷新页面通过 Auth 顶层跳转恢复，不用 iframe 或第三方 Cookie。
- 当前退出和全部退出；退出后 sessionStorage 中只保留暂停恢复标记，主动点击登录才恢复。PKCE/state 待处理信息也使用 SDK 的短期 sessionStorage；不持久化 Token。
- 普通用户展示自身账号和 userId，以及自己的空间和待处理邀请；白名单管理员再加载平台应用、用户及全局审计入口。任何隐藏按钮都不替代服务端鉴权。
- 空间页提供团队创建、名称/版本、归档恢复、成员角色/移除/退出、邮箱邀请及撤销、站内同意/拒绝、空间审计；当前成员权限决定操作，详见 [空间 API](space-api.md)。Owner 交接未实现，等待范围确认。
- 应用创建、详情/版本、动作目录及启停；登录客户端创建、精确回调/scope/状态修改。
- 服务创建、轮换/停用；新 Secret 默认遮挡，仅存页面内存，关闭提示、切换页面、退出或 pagehide 时清除。不会自动复制到剪贴板或保存到本地。
- 用户列表、已验证邮箱详情、启停；全局审计列表。
- 所有列表使用后端游标分页；移动端表格在自身区域横向滚动，页面整体不横向溢出。
- 改配置、凭据和用户状态前弹出原生确认对话框，默认焦点在取消；版本冲突要求重新读取，不自动覆盖。
- 写请求不自动重试；网络未知结果明确提示先读取当前状态，避免重复创建或轮换。退出区分已确认撤销与仅清除本地状态。

接口字段和撤销语义见 [平台 API](platform-api.md)。全部退出也通过确认框，但不会退出 Google/Apple 自身账号。
所有请求沿用 Auth Origin、TLS、显式 Bearer、no-store、no-referrer 与 CSP；管理 API 不发送 Cookie。

## 个人账号安全中心

普通账号可在控制台查看自己的登录会话和安全事件，无需平台管理员白名单。会话列表按完整认证根分组，显示当前标记、认证/活动/到期时间、有效/过期/撤销状态及历史应用授权数，不声称识别物理设备。撤销确认默认为取消；确认撤销当前根会退出本页，刷新不自动恢复。

独立审计入口只返回自身账号安全事件，不混入平台/空间审计。未知写入结果不显示撤销成功，也不自动重试。HTTP 契约及测试边界见 self-account-api.md。已使用真实浏览器验证查询、取消、当前会话撤销与刷新，数据库核实关联授权撤销及单条成功审计。
- 本机打包 Jar + 隔离 MySQL/Redis + 内置浏览器，真实验证：顶层 Cookie 恢复、全部退出后的刷新暂停、主动密码重新登录、SDK 回调兑换后进入平台页。
- 空白名单重启后同一测试账号只看到自身 userId；恢复指定测试白名单后再次加载管理功能。
- 浏览器实际创建空动作目录测试应用、更新名称，版本从 0 变 1，并在审计页看到对应 SUCCESS/requestId。
- 配置确认弹窗取消不提交；中文用户/审计列表可读取。390px 窄屏与 1280×900 桌面已检查；窄屏 document 宽度与内容宽度均为 390px。
- 后续空间切片在普通账号/空白名单下验证团队创建、Owner 成员读取、自身测试邮箱邀请及明确接受、站内列表同步和空间审计；390px/1280px 复查通过。跨账号提权或移除仍只由 HTTP 测试覆盖，未执行浏览器高影响提交。

上述操作仅作用于隔离测试数据，没有变更真实用户凭据、授予实际业务权限或修改 GoalBoard。
服务 Secret 创建/轮换及用户启停有实际 HTTP/SQL 回滚和撤销测试；浏览器端未执行这些高影响动作的完整提交验收。
独立主域名的浏览器 SDK 自定义登录 demo、注册/找回表单实际收件、Google/Apple/SMTP、生产代理/TLS及容量仍待验收。控制台同源成功不能代替这些不同范围的证据。
