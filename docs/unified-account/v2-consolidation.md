## 2. 最终产品形态

一套 V2 用户和登录方式、一套会话协议、一套租户与成员模型、一套订阅席位及权益服务。Auth、Work、Club 可以有各自的界面，均使用这些中央事实，不再保留 V1 认证分支、旧 SDK 或失败后降级。

- 登录方式按当前需求为邮箱密码、+86 手机验证码、Google、GitHub；不因 V1 曾有 Apple 而新增 Apple 接续。
- 组织使用 V2 租户模型和 OWNER/ADMIN/MEMBER 三角色；不保留独立的 V1 Team 模型，不为旧 VIEWER 或归档记录设计转换。若以后需要只读角色或归档，是独立产品功能。
- 创建资格按服务端策略：SELF_SERVICE 默认允许当前登录用户创建并成为所有者；PLATFORM_ONLY 仅平台人员创建并分配所有者。平台代建始终需要 TENANT_CREATE。
- 平台权限、租户管理角色、业务资源权限与商业权益分开。付费资格不能代替资源访问授权，租户管理员不自动获得付费能力或平台权限。
- 账号、租户、订阅与权益由 Auth 管；Home、项目与文档等业务内容仍归当前 owner。统一协议不新增内容共享、同步或收费拦截。

## 3. 从当前任务中删除的工作

以下事项不再作为设计目标、交付前置或待确认问题：

1. V1 Token、根会话、Cookie、旧 Personal 凭据的读取、转换和恢复。
2. 旧用户 ID/密码哈希/未验证邮箱补验证/Apple 身份的存量接续与映射。
3. 旧 Team、VIEWER、归档数据和权限矩阵的兼容转换。
4. 旧 SDK 导出、旧 API 别名、双协议运行、自动降级和兼容窗口。
5. 存量盘点、双写、逐批切换、恢复 V1 路由与数据的方案。

新建 V2 用户仍需执行邮箱验证、身份唯一性、最后一种登录方式保护与撤权规则；这些是当前安全与业务要求，不属于旧版兼容。

AUTH-11 等历史演练可以留作历史证据，不是本次 V2 替换的验收要求。实现时连同 V1 专属代码清理只为兼容旧版存在的工具与测试；对当前 V2 仍有价值的安全断言保留，不能把删旧测试当作新功能通过。

## 5. Work 仍需解决的生命周期问题

当前安装身份用于确定个人 Home，现有 V2 AccountSessionManager 则由 Home 内 Host 持有。即使没有旧数据，这个启动顺序仍需调整：安装入口先完成 V2 身份确认，再经当前 Home 选择和租约检查进入 Home，账号管理复用同一套协议。

保留安装会话、本机控制令牌、Home 租约与本地 actor 的不同职责。退出、换号或撤权后取消原请求，迟到的刷新或后台写入不得污染新 Home。保留 #1965 桌面系统浏览器回跳的校验，不再恢复旧 V1 回跳。

本次不用兼容旧 SecretStore，但新的 V2 存储仍须按当前环境、客户端和 Home 隔离；不能通过一个公开 accessToken 出口让浏览器、插件或模型获取中央凭据。

## 10. 首轮统一实现与本地验证（2026-11-09，追加清理前）
